


# 题目
给定一个二叉树的根节点 `root` ，和一个整数 `targetSum` ，求该二叉树里节点值之和等于 `targetSum` 的 **路径** 的数目。

**路径** 不需要从根节点开始，也不需要在叶子节点结束，但是路径方向必须是向下的（只能从父节点到子节点）。

**示例 1：**

![](https://assets.leetcode.com/uploads/2021/04/09/pathsum3-1-tree.jpg)

**输入：**`root = [10,5,-3,3,2,null,11,3,-2,null,1], targetSum = 8
**输出：**3
**解释：**和等于 8 的路径有 3 条，如图所示。

**示例 2：**

**输入：**`root = [5,4,8,11,null,13,4,7,2,null,null,5,1], targetSum = 22
**输出：**3



# 题解

```java
class Solution {
    int ans = 0;
    public int pathSum(TreeNode root, int targetSum) {
        Map<Long,Integer> cnt = new HashMap<>();
        cnt.put(0L,1);
        dfs(root,0L,targetSum,cnt);
        return ans;
    }
    void dfs(TreeNode root,Long s, int targetSum,Map<Long,Integer> cnt ){
        if(root==null) return;

        s+=root.val;
        ans += cnt.getOrDefault(s-targetSum,0);
        cnt.merge(s,1,Integer::sum);
        dfs(root.right,s,targetSum,cnt);
        dfs(root.left,s,targetSum,cnt);
        cnt.merge(s,-1,Integer::sum);
    }
}
```


## 代码讲解思路：

结合代码一步步来看
### 1. 代码结构概览

```java
class Solution {
    private int ans;  // 存最终答案，即符合条件的路径总数

    public int pathSum(TreeNode root, int targetSum) {
        Map<Long, Integer> cnt = new HashMap<>();
        cnt.put(0L, 1);                // ① 初始化：前缀和为0出现1次（空路径）
        dfs(root, 0, targetSum, cnt);  // ② 从根开始遍历
        return ans;
    }

    private void dfs(TreeNode node, long s, int targetSum, Map<Long, Integer> cnt) {
        if (node == null) {
            return;                     // ③ 空节点直接返回
        }

        s += node.val;                  // ④ 更新当前路径的前缀和
        ans += cnt.getOrDefault(s - targetSum, 0); // ⑤ 统计以当前节点为终点的路径

        cnt.merge(s, 1, Integer::sum);  // ⑥ 当前前缀和计数+1，进入“当前节点的影响范围”
        dfs(node.left, s, targetSum, cnt);   // ⑦ 递归左子树
        dfs(node.right, s, targetSum, cnt);  // ⑧ 递归右子树
        cnt.merge(s, -1, Integer::sum); // ⑨ 回溯：当前前缀和计数-1，撤销影响
    }
}
```
### 2. 回溯是每一层都要回溯吗？

**是的，每个节点在递归返回时都要回溯。**

回溯的目的是：**哈希表 `cnt` 里只保留“从根到当前处理节点这条路径”上的前缀和，不能把其他分支的前缀和混进来。**

当你在处理一个节点时，你增加了它的前缀和计数（`cnt.merge(s, 1, ...)`），这一步代表“我这条路径上现在有了这个前缀和”。  
当你处理完它的左右子树，准备返回上一层时，如果不减掉这个计数，那么：

-   返回上一层后，上一层会去走它的右兄弟（如果有的话）。
-   右兄弟的路径里，会“看到”你刚才留下的前缀和，从而错误地认为那个前缀和也在这条新路径上，算出错误答案。

所以必须**在退出节点时恢复现场**，把刚才加进去的计数再减掉。这就是为什么每个节点都要做回溯。
### 3. 回溯的位置在哪里？

回溯操作就是第 ⑨ 行：

```java
cnt.merge(s, -1, Integer::sum);
```

它发生在：

-   当前节点已经计算完了答案（⑤）；
-   当前节点已经把它的前缀和加入哈希表（⑥）；
-   已经递归处理完了左子树（⑦）和右子树（⑧）；
-   即将返回给父节点的时候。

**顺序不能错**：一定是先递归左右子树，再回溯。因为左右子树的遍历需要当前节点的前缀和存在，所以不能提前撤销。

### 4. 代码逐段解释

#### 主函数

- `Map<Long, Integer> cnt`：记录“前缀和→出现次数”。key 类型为 `Long` 是因为树节点值可能很大，累加可能超出 int。
- `cnt.put(0L, 1)`：必须加这一条。想象一条从根节点出发，刚好整个路径和等于 `targetSum` 的路径，我们需要一个“前缀和为 0”的祖先。空路径就是那个祖先。

#### dfs 函数

参数：
- `node`：当前处理的节点。
- `s`：从根到 `node` **父节点**的前缀和（看注释：s 表示从根到 node 的父节点的节点值之和，node 尚未计入）。进入函数后才加上当前节点值。
- `targetSum`：目标和。
- `cnt`：共享的前缀和计数哈希表。

**④ `s += node.val`**  
现在 `s` 变成了从根到当前节点的前缀和。

**⑤ `ans += cnt.getOrDefault(s - targetSum, 0)`**  
找有多少个“祖先节点”的前缀和等于 `s - targetSum`。  
因为 `当前前缀和 - 祖先前缀和 = 路径和`，如果这个路径和等于 `targetSum`，那么 `祖先前缀和 = 当前前缀和 - targetSum`。查表得到这些祖先的个数，就是以当前节点为终点的路径条数。

**⑥ `cnt.merge(s, 1, Integer::sum)`**  
将当前节点的前缀和 `s` 加入哈希表，计数 +1。  
这样，当遍历它的子树时，这个 `s` 就可以作为“祖先”被下面的节点找到。

**⑦⑧ 递归左右子树**  
此时哈希表里已经包含了当前节点的前缀和，子树中的节点就可以利用它来统计从当前节点开始的路径。

**⑨ `cnt.merge(s, -1, Integer::sum)`**  
回溯：把刚才加进去的 `s` 的计数减 1。  
如果计数减到 0，`merge` 的特性会删除这个键（因为 `Integer::sum(0, -1)` 等于 -1，但实际 `merge` 在值变为 null？这里需要注意：`cnt.merge(s, -1, Integer::sum)` 会把旧值和新值 -1 相加，如果旧值是 1，结果 0，merge 不会删除键，只是值变成 0。但我们希望是恢复原状。实际上标准写法是 `cnt.put(s, cnt.get(s) - 1)` 并在为 0 时 remove，但这里用 `merge(s, -1, Integer::sum)` 也能达到效果，只是会留下 0 值的键，不过不影响正确性，因为 `getOrDefault` 遇到 0 也是返回 0，不会多统计。更严谨的做法是 `cnt.compute(s, (k, v) -> v == 1 ? null : v - 1);`。这里代码为简洁用了 merge 并相信 0 不影响，实际面试可以提一下。）  
这步完成后，哈希表的状态就恢复到了进入这个节点之前的样子，不会影响父节点的其他分支。

### 5. 为什么必须回溯？举个例子

假设这样一棵树：

```
    10
   /
  5
 /
3
```
targetSum = 8。

过程推演（只关注关键步骤）：
- 进入根节点 10，s=10，cnt: {0:1, 10:1}
- 进入节点 5，s=15，查 15-8=7 没有，cnt 加入 15:1
- 进入节点 3，s=18，查 18-8=10，有 10:1，找到一条路径 5->3 (15-10=8? 等等需要仔细，从根10到3前缀和18，祖先10前缀和10，相减得8，即路径 5->3)。答案+1。
- 处理完 3 返回 5 时，必须回溯把 18 的计数减掉，不然如果 5 还有右子树，就会错误地认为还有一个前缀和 18 可用。

如果忘记回溯，cnt 里就会残留其他分支的前缀和，导致错误。

### 总结

- 回溯是**每个节点**都要做的，位于递归左右子树之后。
- 代码中的 `cnt.merge(s, -1, Integer::sum)` 就是回溯操作。
- 回溯保证了哈希表只反映“当前活跃路径”上的前缀和，是前缀和解法正确性的关键。
