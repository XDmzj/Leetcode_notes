# 题解






## DFS深度优先
递归二叉树，先对右子树进行递归，如果此时节点的深度和ans此时的大小相同时，将其存入ans

注意这里是大小，不是容量，大小初始为0，此时节点深度也为0（根节点），存入、递归之后，大小为1，右节点深度也为1，存入，直到右子树被遍历完毕
然后遍历左子树，左子树的前几个节点深度不够，不会存入，深度等于ans的大小之后才会开始存入

关键变量是：递归树的深度记录为depth，下一层递归时+1


```java
class Solution {
    public List<Integer> rightSideView(TreeNode root) {
        List<Integer> ans = new ArrayList<>();
        dfs(ans,root,0);
        return ans;
    }
    public void dfs(List<Integer> ans , TreeNode root, int depth){
        if( root==null) return ;
        if(depth == ans.size()){
            ans.add(root.val);
        }
        dfs(ans,root.right,depth+1);
        dfs(ans,root.left,depth+1);
    }
}
```


## BFS广度优先
每一层选出最后面的元素，记录一下，思路简单，但是开销大，效率低
熟悉广度优先的代码该怎么写
```java
class Solution {
    public List<Integer> rightSideView(TreeNode root) {
        //感我此言良久立
        if(root==null) return List.of();
        List<Integer> ans = new ArrayList<>();
        List<TreeNode> cur = List.of(root);
        while(!cur.isEmpty()){
            ans.add( cur.getLast().val);
            List<TreeNode> next = new ArrayList<>();
            for(TreeNode n : cur){
                if(n.left!=null) next.add(n.left);
                if(n.right!=null) next.add(n.right);
            }
            cur = next;
        }
        return ans;
    }
}
```





## 二刷：得知了dfs时间复杂度和空间复杂度的优势在哪

**空间复杂度**
**DFS（深度优先）只记住“一条线”，BFS（广度优先）要记住“一整片”。**
我们用一个具体到夸张的例子感受一下

想象一棵“家族树”，有一千万人

假设这是一棵非常茂盛、规整的家族树，有大约 1000 万个成员。

BFS 的记忆方式：要记住整层的人

BFS 是一层一层拜访的。当它拜访到最底层时，队列里会**同时站着最底层的全部人**。

- 最底层有多少人？在这类树里，最底层大约占了总人数的一半，也就是**超过 500 万人**。
    
- 这就像组织一场超大型聚会，你的大脑（内存）需要同时记住 500 万张脸长什么样，这几乎是不可能的。
    
- 这就是 BFS 的空间复杂度，和树的**宽度**有关，极端情况下会非常巨大。
    

DFS 的记忆方式：只记住一条血脉

DFS 则不同，它是一条路走到底再回头。它采用“根 -> 右 -> 左”的路线，先一口气找到整棵树最右边的那一支血脉。

- 它需要同时记住多少人？**只需要记住从老祖宗到当前这个人，这一条线上的所有祖先。**
    
- 因为树是规整的，这条线再长，也不过是树的**高度**，大概也就 20 多个人（因为 224≈1600万224≈1600万）。
    
- 你的大脑只需要记住这 20 多个人的名字和位置，就能把整个家族的“右视图”画出来。记住 20 个人对比 500 万人，这个差别就是天壤之别。


**所以，对于“右视图”这道题，DFS 空间效率高的原因是：**  
它用一条线（高度）的记忆成本，完成了 BFS 用一整片（宽度）才能完成的事。在绝大多数正常的树里，线的高度远小于片的宽度。

**时间复杂度**

时间效率：都是 O(n)O(n)，但 DFS 的常数更小

理论上两者都要访问每个节点一次，时间复杂度均为 O(n)O(n)。但在实际运行中，DFS 通常更快，主要来自常数层面的优势：

- **数据结构操作开销不同**
    
    - BFS 需要显式操作队列（入队、出队），在 Python 中即使使用 `deque`，每次操作也有函数调用和对象包装的开销。
        
    - DFS 递归只使用系统的函数调用栈，参数传递和返回非常轻量，省掉了维护队列的逻辑。
        
- **省去了一层内层循环**  
    BFS 的典型实现需要一个 `for` 循环来按层处理，区分“当前层最后一个节点”。DFS 只需按“根-右-左”顺序遍历，用一个 `depth == len(res)` 就能直接判断，省去了层级循环的控制开销。
    
- **更友好的内存访问模式**  
    DFS 递归天然沿着一侧子树向下深入，访问的节点在内存中相对靠近，CPU 缓存命中率更高。BFS 的队列在层间跳跃，访问模式更随机，缓存不命中的代价更高。
